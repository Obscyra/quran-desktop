# Quran for Desktop — project memory

Free, open-source (GPL-3.0), ad-free desktop Quran app for Windows and macOS (Linux later).
Tauri 2 + SvelteKit (adapter-static, ssr=false) + Svelte 5 runes + TypeScript. Repo:
https://github.com/Obscyra/quran-desktop (branch `main`, public). Inspired by
https://github.com/quran/quran_android (credit it and keep its Android links in the README; the app now has its own icon).
Data from the Quran.com public API v4. App code is in `app/`; `reference/` (gitignored) holds a clone
of quran_android.

## Architecture (app/src/lib)
- `api.ts` quran.com calls: `fetchVerses` (words with `code_v2` glyph, `v2_page`, tajweed markup,
  audio_url), `fetchIndo` (IndoPak text + 15-line layout via `mushaf=3`), `fetchChapterAudio`
  (per-word segments), reciters, translations.
- `fonts.svelte.ts` loads quran.com page fonts `verses.quran.foundation/fonts/quran/hafs/v2/woff2/p{n}.woff2`
  as `QCF{n}`, cached in IndexedDB (`offline.ts`, DB v3: text, audio, blobs, fonts, indo).
  `has()` must read `tick` to stay reactive.
- `player.svelte.ts` audio engine: lazy audio load (`prepareAudio`), `playVerse` (range + loop),
  `playFrom`, `playWord` (wbw mp3, or segment offline), `goTo`/`jump` for bookmarks and search.
- `reader.svelte.ts` page state incl. two-page spread (even page right, the next odd page left: 2 faces 3). `pages.ts` groups
  words by page/line (normalises by reading order; the API mislabels some verses).
- `settings.svelte.ts` (localStorage `quran.settings.v2`), `bookmarks.svelte.ts`, `ui.svelte.ts`,
  `actions.ts`, `translations.svelte.ts`, `updater.svelte.ts`, `themes.ts`, `platform.ts`.
- Components: `TitleBar` (custom chrome; Verse by Verse | Reading switch; listen/focus/fullscreen/menu),
  `Reader` (sub-bar + modes), `PageSheet` (one Mushaf page; `fit()` sizes text to the widest line),
  `Word`, `End` (verse-end marker), `WordMenu`, `Sidebar` (Surahs | Bookmarks, type `55:13`),
  `PlayerBar`, `Settings`.
- Gotchas: `text-rendering: geometricPrecision` on glyph text (hinting draws stray strokes otherwise);
  word padding in `em` so line fitting scales linearly; `$state.snapshot()` before storing proxies in
  IndexedDB; never `pkill -f "vite dev"` (kills the shell) — use `fuser -k 1420/tcp`.
- Listen-only reciters: `reciters-qa.ts` (92 whole-surah recitations of quranicaudio.com, ids 10000+, generated by `scripts/update-reciters.mjs`; its list API has no CORS so it ships as a file). They have no timings (`ChapterAudio.plain`): no highlight, verse stepping or play-from-verse; the picker groups them under "Listen only" below "Follow along".
- Reciters: `reciters.ts` is quran.com's list with portrait paths (`static.qurancdn.com/<photo>`); recordings
  without word timings (`approx`) get word timings estimated from verse spans in `player.fetchAudio`.
- Reminders / verse of the day: `notifications.svelte.ts` + `NoticeCard.svelte`; system toasts use
  `tauri-plugin-notification` (Cargo + capability added, not yet compiled on Windows).
- Smoothness rules (measured with the CPU throttled 4x, see git log): layout changes (sidebar, player bar) are
  one reflow plus a transform glide, never an animated width/height; the paged reader keeps the current spread and
  its neighbours mounted (neighbours hidden, laid out when idle); long surahs render in batches (`upto` in
  `Reader.svelte`); the sweep layers are made by `sweep.ts`; Settings is an overlay over a mounted reader.
- Left-click a word plays it; right-click opens `WordMenu`. Back/forward trail lives in `player.svelte.ts`.
- Fonts bundled in `app/static/fonts`: KFGQPC Uthmanic Hafs, IndoPak Nastaleeq (from quran.com), Inter, and
  `arabic/` (Amiri Quran, Noto Naskh Arabic, Scheherazade New, OFL): Windows has none of the three.
- Tray and background (`src-tauri/src/lib.rs`): tray icon (Open / Quit), `tauri-plugin-window-state` (size, position, maximized;
  not VISIBLE, so a window hidden in the tray never makes the next launch start hidden), `tauri-plugin-autostart` (starts with
  `--hidden`). Closing the window hides it when `settings.background` is on: done in the JS `onCloseRequested` in `+page.svelte`
  (a Rust close handler would be undone by that listener). A pending update still installs on close.
- `PageSheet.fit()` divides measured widths by the page's own transform scale (`k`), so it is right even during a glide;
  the Reader glide skips a page that was hidden (zero size). Tajweed class names contain hyphens (`custom-alef-maksora`).
- Single instance: `tauri-plugin-single-instance` must be the first plugin (a second launch shows the running window). Window size is saved
  400 ms after the last resize/move by `remember_window` in `lib.rs` (the plugin alone only saves on exit, rare for a tray app).
- Scroll views: `settings.lockPlaying` + `centerPlaying`/`playingBounds` in `Reader.svelte` (verse centred whole; taller verses follow the word);
  unlocked, a `.back` arrow shows when the verse is off screen. Rects are divided by `k` (interface zoom).
- Window fit (`+page.svelte`): `fit()`/`refit()` write the real `window.innerHeight` to `--vh` (used by `.app` height) and reset the scroll on resize, focus, scroll and visibilitychange. A window hidden in the tray can come back with a stale 100vh and a scrolled page (top bar and player lost); this fixes it. Check it on real Windows, not in a browser.
- Settings `playerHover`: the player bar floats over the bottom edge and shows on hover (`PlayerBar.svelte`).

## Bundled Quran data (works with no connection)
- `app/scripts/bundle-data.mjs` (`npm run bundle`) downloads the surah list, the Arabic text of all 114 surahs (default translation Saheeh) with
  Tajweed markup and IndoPak spelling, and the 604 page fonts into `app/static/data/` and `app/static/fonts/qcf/` (about 120 MB, gitignored,
  so every checkout and CI run must run it: `release.yml` does). The installer carries them; `api.ts` and `fonts.svelte.ts` read them first
  and only go online for other translations and audio (audio is never bundled; the Audio manager downloads it).
- `datasync.svelte.ts`: a weekly background check (25 s after start, online only) compares the provider's text, IndoPak spelling and page-font sizes (`data/manifest.json`, written by the bundle script) with what the app has, and keeps changes in IndexedDB (`<surah>:fresh`, `fonts`, `quran.fresh.fonts`), read before the bundled copy. Changes must pass `sound()` (no verse or word lost).
- Word meanings follow the translation's language (`languages.ts`, `api.extrasOf`); the bundled words are English. Cached text keys end in `:2`.
- First run (`settings.firstRun`): `Welcome.svelte` (theme, size, mode, script, language, word meanings; Skip on every step; flag `quran.welcomed`).
- App icon master is `app/src-tauri/icon-source.png` (`npx tauri icon src-tauri/icon-source.png`, then delete the generated `icons/android` and `icons/ios`). It is the green icon with the gold calligraphy; the golden squircle version (commit `67c2209`) was set aside at the owner's request.
- Run `npm run bundle` once before a local build or dev session; a build without the files still works but fetches from the network.

## Website
- Own repo https://github.com/Obscyra/quran-desktop-site, hosted on Netlify at https://qurandesktop.netlify.app (GitHub Pages is switched off). The site address is written into `index.html`, `robots.txt`, `sitemap.xml` and `llms.txt`: change all four if a custom domain is added. `_headers` holds the security headers and CSP (keep `connect-src` in step with what `app.js` fetches). Kept in `website/` here (excluded from this repo via `.git/info/exclude`; commit and push from inside that folder). The page has gold Arabic calligraphy phrases as CSS pseudo-elements (`:root{--gold}`, placed per section so they never sit behind screenshots), features alternate sides (text centred against the screenshot), and the "Try the reader" demo works like the app: real audio (`audio/fatiha.mp3`), word timings in `data.js` (`window.FATIHA_T`), Sweep / Fill / Line highlight (the sweep is a clipped accent copy of the word, as in the app). Step videos fade in over a poster image (`.vid.ready`) to avoid a white flash. Headless Chromium cannot decode the VP9 webm, so check video in a real browser. The download buttons ask the GitHub API for the latest release's `.exe` / `.dmg` (`app.js`, `data-dl`).

## Run and test
- UI in a browser: `cd app && npm install && npx vite dev --port 1420` then
  `http://localhost:1420/#/55?os=windows` (`?os=` previews other chrome).
- Type check: `npm run check` (must be 0 errors, 0 warnings).
- Playwright scripts used for tests live in the session scratchpad (`pw/`); write new ones with the
  `playwright` npm package. Check line overflow/overlap, glyph fonts, word menu, verse-only playback,
  and offline (download, then abort non-localhost requests and reload).

## Build the Windows installer (only when asked)
WSL2 with Windows interop. Build happens in `C:\Users\magnum\quran-build` (copy of `app/`):
1. `rsync -a --delete --exclude node_modules --exclude .svelte-kit --exclude build --exclude target app/ /mnt/c/Users/magnum/quran-build/`
2. `echo '{"bundle":{"createUpdaterArtifacts":false}}' > /mnt/c/Users/magnum/quran-build/src-tauri/tauri.local.json`
3. `powershell.exe -NoProfile -Command 'cd C:\Users\magnum\quran-build; $env:Path += ";C:\Program Files\nodejs;$env:USERPROFILE\.cargo\bin"; npm.cmd run tauri build -- --config src-tauri\tauri.local.json'`
   (run in background, ~5+ min; PowerShell reports exit 1 from stderr even on success).
4. Installer: `quran-build\src-tauri\target\release\bundle\nsis\Quran_<version>_x64-setup.exe`.
   (Tauri 2 signs with env `TAURI_SIGNING_PRIVATE_KEY`, content or path, not `_PATH`. To sign a finished exe: `npx tauri signer sign -f ~/.tauri/quran-desktop.key -p "" <exe>`.)
   Copy to `D:\Downloads\Quran-Beta\` (`/mnt/d/Downloads/Quran-Beta/`) with a README.txt.
Replacing an installer on an existing release (only when asked): upload the exe and its `.sig` with `gh release upload --clobber` and put the new signature in `latest.json`. The copy can fail with "Permission denied" if an installer is running; don't kill the owner's process. Don't install on the owner's PC unless asked. Don't use `-ExecutionPolicy Bypass`.

## Releases and updates
- `.github/workflows/release.yml`: pushing a `v*` tag builds Windows (.exe) + macOS (.dmg), signs update
  artifacts, publishes `latest.json`. Releases are normal (non-pre-release) even for `-beta` tags, so the updater sees them; notes come from `.github/release-notes/<tag>.md` + `footer.md`.
- Needs secrets `TAURI_SIGNING_PRIVATE_KEY` (+ `_PASSWORD`, empty). Key is `~/.tauri/quran-desktop.key`;
  the public key is in `app/src-tauri/tauri.conf.json`. Losing the key breaks updates for installs.
- Installed apps only see updates from a public repo's non-prerelease `latest`.
- Uninstaller (`src-tauri/windows/hooks.nsi`) removes app data unless `$UpdateMode`; verified earlier. The same hooks file defines `MUI_UNICON` so the uninstaller shows the Quran icon (hooks are included before Tauri's `UNINSTALLERICON` check).
- Version lives in `app/package.json`, `app/src-tauri/tauri.conf.json`, `app/src-tauri/Cargo.toml`
  (CI overrides from the tag).
